    记录流搭建

    11月因工作调整，想着把过往资料整理一下便于后续使用。

    一、网盘内容管理

    从工作开始就比较喜欢云端存储，主要是国产的一些公司。腾讯微云，360云盘，百度等。使用的初衷是可以脱离设备无缝衔接手中的事项。最终因为百度网盘比较稳定用了几年，把生活照片，工作内容，常用软件等一股脑都同步进去了。

    整理的初衷是

    1. 内容太杂：大部分没有系统学习过如何分类归档的人都有【收藏过=学过】的不良习惯
    2. 内容过旧：近一两年还比较热门的活动玩法，可能再过个两年看已经毫无新意了，当时感觉是内部机密的项目经验，过两年再看项目文档也不过如此，自己随便写写都比这个好。因为事情在发展，人是会进步的。
    3. 收纳不规范：以个人擅用工具搜索为掩护，文件没有框架结构的存放，命名不标准，内容积累多了之后很难查找。

    记录整理的过程

    1. 文件整理

      百度网盘，年费178元太贵，而且软件比较臃肿，之前更习惯上传个人向的内容，照片、方案归档等。

      123云盘，三年210元，支持mountain duck挂载，20T容量，赶上自己想接触一些新实物，果断切换

      onedrive，之前受限科学上网的能力，对微软谷歌Facebook等公司不够了解，使用之后发现onedrive还挺良心，公司电脑和个人电脑同步起来简直太丝滑了，免费15G。

    2. 于是决定，在这三个drive中进行分类，把个人的数字资产梳理一番

      onedrive和123云盘文件结构一样，onedrive用于高频实时的同步，123云盘作为储存每月接受一次归档覆盖，目前又开通了115网盘最二次归档储存。

    文件内容的结构

    • 桌面：实时工作内容，高频使用
    • 工作项目：存放具体任务，按年份+项目名组织
    • 知识资产：数字智库（述职、方法论、模板等在此）
    • AI牛马：智能体撰写的材料，用户加工成汇报方案，只看不写
    • 数据表：Excel数据合集
    • 图片视频：项目中需要储存的素材-低频
    • 个人归档：历史资料，低频访问

    命名建议：[YYYYMMDD]_关键词_版本.后缀
    例如：20241127-用户运营SOP-v2.docx

    按照同步盘-备份盘-归档盘的流程，按照结构阶段性梳理文件，后续查找使用的效率会更好

    意外的收获

    一、在梳理过程中发现了Qspce这个软件。痛点是

    1. 我再onedrive和挂载盘里这么多文件来回拖动，实在是太琐碎复杂了。
    2. 根据新的文件结构创建文件夹可以批量搞定了。
    3. 之前还差点买了压缩软件用于加密压缩，把我的数字资产通过加密压缩储存起来，这下Qspace就搞定了。

    二、创建的个人博客

    也是因为工作变动，自己可以独立负责一条线了，未来肯定会有一些业务上的思考，于是想是不是能有blog能存储我的内容，跟着AI截图一步步的搭建出来GitHub.io的个人博客了。虽然看的人会很少，也不会有什么影响力，但是在互联网中留下了痕迹，为互联网的中文内容增加几个字节哈哈哈

    三、因为博客又折腾出来的编辑器typora

    之前都是依赖于现有的编辑文档，如语雀、石墨、飞书、钉钉文档等。感觉班味都太浓，而且在别人的平台上。常规的记事本可玩性又不高，于是发现了typora编辑器，学习一下行业通用的markdown语法和国际接轨。

    然后有衍生出来，文档的流转。

    inbox=闪念每天杂七杂八的都能往里面记录，每日必清

    dailylog=把inbox的内容吸收整理沉淀进来，顺便记录一些工作日报之类的留个痕迹

    project=项目相关的文档，应该是这个文件架构里第二有价值的内容了。第一是个人的思考

    assets=查了一下好像叫【资产】，个人最优质的资产就在自己脑袋中把。个人的沉淀都放这里

    archive=归档的内容，长时间不看的，低频的，例如半年前的工作记录放到这里吧

    publish=可以发布到GitHub上的内容

    把typora的文档都建在onedrive网盘上了，随时同步。一会回家就试试我创建的这些是不是都到家啦

    My first blog

    对着AI一步一步的装编辑器，调整github的密钥，换了皮肤，终于把博客的一套流程弄完了。搭建的过程比写内容还要快乐。
    就喜欢长技能点的瞬间，未来也不知道要写些什么。
    听说喜欢写作的人，比较喜欢思考。就把这里当成自己的数字花园，记录一些生活，一些技能，以及想分享的一切。
    之前一直使用语雀文档，可能操作路径太简单了吧，经常去做删改，最近学习文件分类，有些低频使用的就要增加他的路径难度，这样每次使用的时候，都是缓慢的打开，缓慢的修改，频次低了反而内容会随着时间的变化留存下来，不至于一直腾地方。

    活动运营 SOP 怎么做

    [2024-07-17] 原创发表 · 活动运营 SOP 怎么做？

    本文深入探讨了活动运营的关键步骤，包括活动立项、方案设计、项目管理等，为读者提供了一套系统的操作框架和实战技巧。

    用户活动是运营的基础技能，小到微博有奖转发，大到公司级部门级的复杂项目，基本都是以活动为载体，分阶段分节奏包装成不同主题，以此来协调资源触达用户，完成运营目标。

    一、按活动目标分类，大致可以分为四类

    • 提规模（拉新 & 裂变）
    • 促活跃（低频变高频、新用户变活跃用户）
    • 促转化（用户付费、内容消费）
    • 任务型（根据领导意愿，比较被动）

    二、活动流程

    小活动流程包含在项目级活动里，这里以项目活动为例进行介绍。

    1. 活动立项 · 策划阶段

    大多情况下活动要么是已经非常成熟，按照年度 / 季度 / 月度按节奏执行，要么是 top-down 做好承接即可。

    当然也有团队比较核心，作为活动 owner，那可能涉及到活动立项规划。立项阶段主要汇报对象为上级领导，汇报形式一般以 PPT 为主，也可以使用文档进行汇报，但要注意汇报内容的逻辑，以及结构化表达。

    2. 立项汇报内容

    • 项目背景：通过什么数据洞察、结合什么契机、发现什么机会、项目必要性
    • 项目目标：达成目标，数据要量化，大概表述预期成果、预期效益
    • 市场分析：从竞品角度、行业角度、目标用户群体进行分析，阐述项目的必要性
    • 项目方案：大概讲清楚项目节奏，各节点时间、里程碑、关键任务及阶段划分
    • 项目预算：得和老板说清楚你准备花多少钱，费用逻辑，资金来源和使用计划
    • 风险评估：如预算紧张、时间紧张、开发周期短、传播渠道缺失等，写清楚风险点以及如何应对

    预算有个总表大概能看清费用逻辑，各板块需要花多少钱。再备一份传播明细、活动方案、后续规划（活动周期、后续活动主题等，告诉领导是系列活动）。

    3. 活动方案组成 · 执行阶段

    • 活动主题 / slogan：一般给俩让领导有个选择。原则是让用户看懂，明白活动内容
    • 活动目的：拉新、促活、促留存、促转化、流失召回
    • 定量目标：具体拉新多少人、GMV 多少，需要具体数字
    • 活动对象：用户分层（针对不同的用户，对应的玩法是什么；大的活动节奏里，需要有效的活动模块以应对不同层级的用户），一般来讲可以对用户进行一个分层，不同层级的用户用什么活动策略承接，简单来分可以分为三层（见下）
    • 活动节奏：预热期、正式期、奖励公布及发放时间
    • 玩法描述：规则、用户须知、玩法等描述。必要的时候需要准备两份描述方案，一份给前端用户，和设计做好沟通，把文字转化为图文形式，便于用户理解活动；一份给设计、开发（或产品）深度沟通，让他们充分了解活动，便于在前后端更好地展示协作
    • 产品规划：活动落地页、活动玩法，如涉及到开发需要提前与产品或技术确认需求
    • 物料设计：活动主视觉、资源位素材、活动页面设计、传播海报等，预估好量与设计对齐需求
    • 投放渠道：活动开始前就需要把渠道盘清楚，渠道盘点、转化率多少应该有个初级的测算，通过合理的逻辑测算出目标。渠道可以从站内站外、线上线下、付费免费几个角度来划分
    • 监控指标：各个渠道埋点监控（便于统计曝光、UV）、关键资源位上线记录、奖励发放监控、活动关键指标监控（如招商进度、内容产出进度、流量增长进度、拉新数据等）
    • FAQ：活动入口、活动参与流程、关键问题回复等

    用户分层：三层

    普通用户 / 吃瓜用户：承担大部分流量贡献。

    中级用户：做好中级用户的承接，有概率转化为核心用户。活动的价值的一部分就是把中频用户转化为高频用户，实现不同层级用户的跃迁。

    核心用户：主要用户价值的贡献者。活动应该 80% 的策略围绕这部分用户产生，包括渠道的触达、转化激励、用户黏性、裂变等。

    4. 项目管理流程

    项目启动会，通过这个会议形式给项目组成员一个仪式感，同时官宣项目的背景、项目目标愿景，项目的架构职责、规范制度等。

    • 明目标：具体的（GMV 提升 50%）、时间节奏、相关性（和项目组成员岗位职责挂钩）、可量化、可衡量
    • 盘资源：抓手是什么、阻力是什么、需要协调什么
    • 定分工：根据目标拆解、分工计划表、明确各版块具体负责人。分工表结构为：部门 → 环节（前 / 中 / 后）→ 事项（运营 / 产品 / 设计 / 传播）→ 具体内容（方案 / 玩法 / 资源位 & 视觉设计物料 / 供应商管理 / 搭建）→ 负责人 → 备注（对具体内容的解释补充）→ 完成情况 → 时间轴
    • 立机制：风险管理、信息透传、沟通机制、知识管理沉淀形成文字记录
    • 复盘：回顾目标结果比对，叙述过程，探究根源，总结规律迭代优化

    三、收尾：60 分方案之后

    以上流程都兼顾到，基本上就是一个 60 分的方案了。剩下的比较关键的是活动执行，以及每个相关方的衔接。活动前一定要充分透传，让活动参与的人了解信息充分，在一个世界里沟通，避免执行时出现理解上的偏差导致落地变形。
